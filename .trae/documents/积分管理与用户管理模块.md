# 积分手动管理 + 积分流水列表 & 用户管理完善

## Context

后台管理概览已有积分来源构成图表（只读汇总），但缺少管理员手动调整用户积分的入口，也无法查看逐笔积分流水明细。同时用户管理页面当前只是 placeholder，无法进行密码重置、停用启用等操作。本次新增「积分流水」页面（含手动调整积分功能）并实现「用户管理」页面。

## 路由设计

### 后端（挂载在 /api/admin 前缀下，均需 authRequired + roleRequired(Admin)）

| 方法 | 路径 | 功能 | DTO |
|------|------|------|-----|
| GET | `/point-log/list` | 积分流水分页列表，可选 userId 筛选 | — |
| POST | `/point/adjust` | 手动调整用户积分（事务） | AdjustPointsDto |
| GET | `/user/list` | 所有用户基本信息 | — |
| PUT | `/user/:id/password` | 重置用户密码 | ResetPasswordDto |
| PUT | `/user/:id/toggle` | 启用/停用账号（防自停） | — |
| PUT | `/user/:id/targets` | 调整作业/游戏目标分钟数 | UpdateUserTargetsDto |

### 前端

- `/admin/point-logs` → `views/admin/pointLogs.vue`（新增）
- `/admin/users` → `views/admin/users.vue`（新增，替换 placeholder）

## 实现步骤（按前端先行工作流）

### 阶段1：前端 types → apis → views → 路由

**1. types/index.ts** — 追加类型：
- `PointSourceType`、`AdminPointLogItem`、`Paginated<T>`、`AdminPointLogListResult`、`AdjustPointsPayload`、`AdjustPointsResult`
- `AdminUserItem`、`ResetPasswordPayload`、`ToggleUserStatusResult`、`UpdateUserTargetsPayload`

**2. apis/admin.ts** — 追加 6 个函数：
- `getAdminPointLogs(params?)` → GET /admin/point-log/list
- `adjustUserPoints(data)` → POST /admin/point/adjust
- `getAdminUsers()` → GET /admin/user/list
- `resetUserPassword(id, data)` → PUT /admin/user/:id/password
- `toggleUserStatus(id)` → PUT /admin/user/:id/toggle
- `updateUserTargets(id, data)` → PUT /admin/user/:id/targets

**3. views/admin/pointLogs.vue**（新增）：
- 页头 + 用户筛选 el-select + 「调整积分」按钮
- el-table 列：用户名 / 变化金额(正绿负红) / 来源类型(中文映射) / 变动后积分 / 描述 / 时间
- el-pagination 分页
- 调整积分弹窗：用户下拉 + 金额输入(允许负值) + 描述

**4. views/admin/users.vue**（新增，替换 placeholder）：

- 重置密码弹窗 + 调整目标弹窗

**5. adminRoutes.ts** — 插入 point-logs 路由，users 路由改指向新组件

**6. AdminLayout.vue** — 菜单插入「积分流水」项（TrendCharts 图标）

**7. 前端验证**：`npm run type-check` + `npm run build`

### 阶段2：后端 DTO → service → controller → routes

**8. admin.dto.ts** — 追加 3 个 DTO：
- `AdjustPointsDto`（userId, changeAmount: int, description?: string）
- `ResetPasswordDto`（newPassword: string, @MinLength(6)）
- `UpdateUserTargetsDto`（homeworkTargetMinutes?, gameTargetMinutes? — 均 @IsInt @Min(0) @IsOptional）

**9. admin.service.ts** — 追加 interface + 6 个方法：
- `listPointLogs(userId?, page, pageSize)` — JOIN users 取 userName，参数化 WHERE 拼接，LIMIT/OFFSET 分页，COUNT 取总数
- `adjustPoints(adminId, input)` — 事务：UPDATE users 积分 → SELECT 新余额 → INSERT point_logs(source_type='admin_adjust', source_id=adminId) → commit/rollback
- `listUsers()` — SELECT 全量用户基本信息
- `resetUserPassword(userId, newPassword)` — hashPassword + UPDATE password_hash
- `toggleUserStatus(userId, adminId)` — 防自停 `userId===adminId → 400`，active↔inactive 翻转
- `updateUserTargets(userId, input)` — 动态 SET 拼装（参照 updateTemplate 模式）

**10. admin.controller.ts** — 追加 6 个 asyncHandler 函数

**11. admin.routes.ts** — 追加 2 个路由分组 + import

**12. 后端验证**：`tsc --noEmit` + `npm test`

### 阶段3：联调

- 前端 vite proxy 调本地后端
- 覆盖正常流 + 边界：changeAmount=0 / 自停 / 不存在用户 / 空描述

## 关键约束

1. **事务化积分调整**：照搬 redemption.service.ts 事务模板（getConnection → beginTransaction → UPDATE → SELECT → INSERT → commit → catch rollback → finally release）
2. **防自停**：toggleUserStatus 入口 `userId === adminId → throw 400`
3. **DTO whitelist**：所有请求体字段在 DTO 中显式 @IsXxx 装饰
4. **changeAmount=0 防御**：class-validator 无 @NotEquals(0)，在 service 层显式判断
5. **儿童访问后台**：roleRequired(Role.Admin) 中间件自动返回 403
