# 02 - 核心架构分析

## 一、应用入口 (main.ts)

### 1.1 文件概述
应用入口文件，负责创建 Vue 应用实例并配置所有插件。

### 1.2 代码结构
```typescript
import { createApp } from 'vue'
import { createPinia } from 'pinia'
import '@assets/styles/main.scss'              // 全局样式
import 'element-plus/dist/index.css'           // Element Plus 样式
import ElementPlus from 'element-plus'          // Element Plus 主模块
import App from './App.vue'                    // 根组件
import router from "@/router/index"            // 路由配置
import * as ElementPlusIconsVue from '@element-plus/icons-vue'

const app = createApp(App)

// 注册插件
app.use(createPinia())     // Pinia 状态管理
app.use(router)            // Vue Router 路由
app.use(ElementPlus)       // Element Plus UI

// 注册所有图标组件为全局组件
for (const [key, component] of Object.entries(ElementPlusIconsVue)) {
  app.component(key, component)
}

app.mount('#app')
```

### 1.3 初始化流程
1. 创建 Vue 应用实例
2. 注册 Pinia 状态管理
3. 注册 Vue Router 路由
4. 注册 Element Plus UI 组件库
5. 全局注册所有 Element Plus 图标
6. 挂载到 #app 容器

## 三、路由系统 (router/)

### 3.1 路由核心配置 (router/index.ts)

#### 路由架构设计
```
路由分为四大模块：
├── UserLayout (/)      - 用户主布局（需登录）
│   ├── publicRoutes    - 公开路由（首页、商品详情、筛选）
│   └── mainRoutes      - 需要认证的路由（购物车、订单、个人中心等）
├── AuthLayout (/auth)  - 认证布局（登录、注册、找回密码）
├── AdminLayout (/admin)- 管理后台布局（需管理员权限）
└── EmptyLayout (/:pathMatch) - 空布局（404页面）
```

#### 白名单机制
```typescript
const whiteList = [
  '/auth/login', '/auth/adminLogin', '/auth/register',
  '/auth/forget', '/home', '/filter'
]
const dynamicPatterns = [/^\/product\/\d+$/]  // 商品详情页
```
- 白名单路由不需要登录即可访问
- 商品详情页通过动态正则匹配

#### 路由守卫逻辑 (beforeEach)
```
1. 检查是否在白名单 → 直接放行
2. 检查登录状态
   ├── 已登录 → 检查权限（管理员/卖家/普通用户）
   └── 未登录 → 重定向到登录页，携带 redirect 参数
```

#### 权限层级
```
requiresAuth: true    - 需要登录
requireAdmin: true    - 需要管理员/超级管理员/物流权限
requireSeller: true   - 需要卖家身份（可能需要二次验证）
```

## 四、状态管理 (stores/)

### 4.1 Auth Store (stores/auth.ts)

#### 核心职责
- 用户登录/注册/登出
- Token 管理与持久化
- 权限角色判断
- 卖家身份验证

#### 状态定义
```typescript
token: string                      // JWT Token
user: object                       // 用户基本信息
isLogin: computed                  // 是否已登录
isMerchant: ref                   // 商家申请状态
isSeller: ref                     // 卖家身份（持久化）
isUser/isAdmin/isTransport/isMaxAdmin: computed  // 角色判断
```

#### JWT 解析
```typescript
const myJwtDecode = (token: string | null): MyJwtPayload | null => {
  // 移除 "Bearer " 前缀并解码
  const raw = token.replace(/^Bearer\s+/i, '')
  return jwtDecode(raw) as MyJwtPayload
}
```
JWT Payload 包含：sub(用户名), username, exp(过期时间), role(角色), userId

#### 权限判断逻辑
```typescript
const getRedirectPath = () => {
  if (isAdmin || isMaxAdmin || isTransport) {
    return '/admin'   // 管理员跳转后台
  } else {
    return '/home'    // 普通用户跳转首页
  }
}
```

#### 卖家身份验证流程
1. 登录时调用 `verifySellerStatus()`
2. 通过 API `isMerchant2(userId)` 查询服务端状态
3. 更新 `isSeller` 并持久化到 localStorage

### 4.5 Orders Store (stores/orders.ts)

#### 核心职责
- 订单创建与管理
- 订单状态流转
- 批量支付处理
- 物流配送管理

#### 订单状态枚举
```typescript
enum OrderStatus {
  PENDING = 'pending',      // 待处理
  CONFIRMED = 'confirmed', // 已确认
  PAID = 'paid',           // 已付款
  SHIPPED = 'shipped',     // 已发货
  DELIVERED = 'delivered', // 已送达
  COMPLETED = 'completed', // 已完成
  CANCELLED = 'cancelled', // 已取消
  REFUNDED = 'refunded'    // 已退款
}
```

#### 支付流程 (executeSinglePayment)
```
1. batchCreateUserOrder - 批量创建订单
2. showPaymentConfirmation - 显示支付确认弹窗
3. singlePayment - 执行支付
4. batchUpdateOrderStatus - 更新订单状态
5. 失败则 rollbackOrders - 回滚取消订单
```

## 六、核心架构总结

### 6.1 数据流向
```
用户操作 → Views → Stores(业务逻辑) → APIs(HTTP) → Backend
                ↓
         状态更新 → Views 自动响应式更新
```

### 6.2 权限控制
- **路由层**: Vue Router 守卫检查角色
- **视图层**: 组件根据权限显示/隐藏
- **API层**: 请求拦截器自动附加 Token

### 6.3 状态持久化策略
| Store | 持久化 | 说明 |
|-------|-------|------|
| auth | localStorage | Token、用户信息、卖家状态 |
| user | localStorage | 用户详细信息 |
| cart | localStorage | 按用户 ID 隔离 |
| favorite | localStorage | 收藏列表 |
| address | localStorage | 按用户 ID 隔离 |
| orders | 内存 | 仅当前会话有效 |
| book | 内存 | 仅当前会话有效 |
| coupon | 内存 | 需重新获取 |
